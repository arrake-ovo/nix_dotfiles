# `lua/plugins/lsp.lua`

## 作用

这个文件当前只做一件事：在 LSP attach 后调整 `K` 的行为。

## 为什么这样写

- LSP 键位天生是 buffer-local 语义，更适合在 `LspAttach` 后设置。
- 这样可以避免在没有 LSP 的 buffer 里出现无效映射。
- `K` 既是高频键，又已经在你的全局编辑习惯里有自己的位置，所以这里需要显式定义它在 LSP buffer 里的优先级。

## 当前策略

### `K` 变成条件键

当前的 `K` 不是单纯 hover，而是按当前界面状态做两段式行为：

- 如果当前还没有 `noice` 的 LSP 文档窗口，就执行 `hover`
- 如果 hover 或 signature 的文档窗口已经存在，就把焦点切进那个窗口

原因：

- 你希望 `K` 继续承担“查看信息”的自然语义。
- 同时你又希望说明窗口不要一弹出来就自动抢焦点。
- 用同一个键完成“先打开，再进入”，比再增加一个额外焦点键更统一。

### 为什么不直接让 hover 自动进入焦点

- 自动进入焦点会打断当前编辑流。
- 先打开、再按一次 `K` 进入，控制感更强。
- 这也符合你整体配置里“预览默认轻量，进入焦点要显式”的习惯。

## 这份文件的信号

它说明你对 LSP 的态度是保守覆盖：

- 不重写整套 LSP 架构
- 只修正最影响手感的交互点
- 优先让 LSP 行为贴合你已经形成的阅读和焦点切换习惯
