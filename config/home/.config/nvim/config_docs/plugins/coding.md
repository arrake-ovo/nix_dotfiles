# `lua/plugins/coding.lua`

## 作用

这个文件目前做两件事：

- 给颜色值增加可视化预览
- 定制 `nvim-treesitter-textobjects` 的跳转键

## 为什么单独放一个文件

- 这类配置都更偏“写代码时直接参与编辑体验”的能力，不是通用 UI，也不是 LSP。
- 单独放在 `coding.lua`，表示你在按能力域拆文件，而不是按插件名字机械拆分。

## 颜色预览配置在做什么

你加了 `catgoose/nvim-colorizer.lua`，用于把文本里的颜色值直接预览出来。

当前配置的行为是：

- 对所有文件类型启用
- 支持 `#rrggbb`、CSS 颜色、`rgb(...)` / `hsl(...)` 一类函数
- 支持 Tailwind 颜色
- 不直接给原文本上底色，而是在颜色值后面显示一个 `■`

## 为什么这样写

- `filetypes = { "*" }` 说明你想让颜色预览不仅出现在 CSS/前端文件里，也出现在 Lua 配置、Markdown、文档和普通文本里。
- `mode = "virtualtext"` 说明你更在意“代码本身保持可读”，而不是把颜色 token 染成一块底色。
- `virtualtext_inline = "after"` 让预览块跟在颜色值后面，阅读顺序自然，也不会把原始文本挤到前面。
- `virtualtext_mode = "foreground"` 表示把这个 `■` 当成一个前景色符号，而不是额外画一块背景，这样视觉上更轻。

## 什么时候可以改成别的模式

- 如果你想要更强的存在感，可以把 `mode` 改成 `background`，直接给颜色值本身上底色。
- 如果你觉得 `■` 太抢眼，可以只改 `virtualtext` 字符，不用动其他逻辑。
- 如果你只想在前端文件里启用，可以把 `filetypes = { "*" }` 缩到具体文件类型列表。

## 当前配置在做什么

定义了四组跳转：

- 下一个函数/类/参数开始
- 下一个函数/类/参数结束
- 上一个函数/类/参数开始
- 上一个函数/类/参数结束

## 为什么这样写

- 你保留了 Treesitter textobjects 的原生风格 `[] + 对象键`。
- 没有把这套动作也改成 Colemak 方向键，说明你认为“结构跳转语法”本身已经足够稳定，不值得再改一层。
- 选择 `function`、`class`、`parameter`，说明你优先覆盖的是最常见的代码导航单位，而不是一次把所有 textobject 都铺满。
