# `lua/config/lazy.lua`

## 作用

这个文件负责插件管理器 `lazy.nvim` 的启动和总装配。

## 为什么这样写

- 这是整个配置的引导层，所以职责单一最重要。
- 文件里只做三件事：保证 `lazy.nvim` 存在、把它加进运行时路径、声明插件加载入口。
- 不把业务配置写进这里，是为了让启动层尽可能稳定、容易排错。

## 关键设计

### 自动 bootstrap `lazy.nvim`

如果本地没有 `lazy.nvim`，就自动 clone。

理由：

- 新机器可以直接启动，不需要先手动装插件管理器。
- 失败时直接输出错误并退出，避免进入半初始化状态。

### `spec`

加载顺序是：

1. `LazyVim/LazyVim`
2. 你的 `plugins`

理由：

- 先吃掉 LazyVim 默认能力。
- 再在你的 `lua/plugins` 中做追加和覆盖。
- 这比完全重写一套插件栈成本更低，也更容易跟上上游。

### `defaults.lazy = false`

你的自定义插件默认不做懒加载。

理由：

- 你的配置还在定形期，先保证行为直接、可预测，比过早追求启动优化更重要。
- 自定义插件越少做隐式延迟，越容易排查键位和交互为何没有生效。

### `performance.rtp.disabled_plugins`

禁用一部分传统运行时插件。

理由：

- 这些插件对你当前工作流价值不高。
- 关闭它们能减少启动负担和潜在行为噪音。
