# `lua/config/keymaps.lua`

## 作用

这个文件承接 `colemak.lua` 之后，放“全局通用但不属于某个具体插件”的键位。

## 为什么不把这些键放进各插件文件

- 它们不是插件专属行为，而是整个编辑器都要遵守的通用操作。
- 放在一起更容易看出你的整体输入法则，例如跳转历史、搜索结果移动、命令模式入口、插入与撤销的重排。

## 关键配置及理由

### `require("config.colemak").setup()`

先初始化 Colemak 层，再定义全局键位。

原因：

- 方向语义是底层规则。
- 上层键位应建立在这层规则已经生效的前提下。

### `gb` / `gf`

- `gb` = jump back
- `gf` = jump forward

这样写的目的，是把跳转历史做成一组语义明确的键，而不是记忆 `<C-o>` / `<C-i>` 这种控制键。

### `sv` / `sh`

把窗口布局切换做成显式命令，而不是依赖手工拖动窗口。

原因：

- 当前配置非常重视导航效率。
- 既然已经在 `colemak.lua` 里重写了窗口方向，那么这里再补“布局重排”是自然延伸。

### `=` / `-`

把搜索结果前进/后退变成更容易够到的按键。

原因：

- `n/N` 仍然可用，但不一定符合你的布局习惯。
- `zz` 一起补上，表示你希望跳到搜索结果后立即把它放回视觉中心。

### `k` / `K` / `l`

- `k` 进插入
- `K` 行首插入
- `l` 撤销

这是一组明显偏“个人输入法”的重排。

原因：

- 你把普通模式里最常用的编辑动作改成了更顺手的位置。
- 这说明整套配置不是“轻度改键”，而是以个人工作流为中心重新布局。

### `;` / `q;`

把命令入口放到 `;`，命令历史放到 `q;`。

原因：

- 命令行在 Vim 里是高频入口。
- 把它前移到更好按的位置，符合“把高频动作前置”的思路。
